## The idea in plain English

A raid run is five splits. Each split's time is modelled as three parts:

1. **A floor** nobody beats — 85% of the fastest split anyone has shown.
2. **Clean execution above the floor**, which is skewed: you can lose a lot more time than you can gain, so it is log-normal.
3. **Skip misses**: each skip on the line either works, or costs a fixed number of seconds, and sometimes ends the run.

Different *lines* through a split (e.g. Thane kill + air door vs the no-kill launch) shift the split by a measured number of seconds.

## Formula

For split `k` on a chosen variant `v`:

```
T_k = c_k + exp(mu_k + sigma_k * Z) + delta_v + sum_j  B_j * loss_j
Z ~ Normal(0, 1)
B_j ~ Bernoulli(1 - p_j)        (1 = skip j missed)
run ends early with probability fatal_j when B_j = 1
c_k = 0.85 * (community best segment k)
```

The median clean split on the reference line is `c_k + exp(mu_k)`. This is a **shifted log-normal**: `log(T_k - c_k)` is normal, with mean `mu_k` and sd `sigma_k`.

**Reference line.** Every profile is measured on one common set of lines: the ones Nanobit's 7:01 used. TexasPete's 6:50 ran different lines, and some of them are now patched. His splits are moved onto the reference line by subtracting the measured line gaps (table below). That way one `delta_v` per variant works for everybody.

### Skips: success and the cost of a miss

The success probability comes from the practice log as the mean of `Beta(1 + made, 1 + missed)` (see bayesian-shrinkage.md). Profiles with no log use a status prior. Record holders get `Beta(19,1)` = 95% for proven skips and `Beta(8,2)` = 80% for new or unverified ones. Runners with no log get `Beta(7,3)` / `Beta(5,5)`. "Unverified" means nobody has done it in a 1.0.1.2 run; that is flagged separately from execution risk.

## Calibrating the record holders: a PB is not a typical run

A personal best is the **best of many attempts**. If we treated the 6:50 as a typical run, we would grossly overstate how often it happens. Nanobit gives two anchors: PB **7:01.97**, and a sum of best of **6:51** after **177 attempts**.

The model assumes `n_k` attempts reach split `k`: 177 → 131 → 97 → 72 → 53. That is 177 starts with 30% finishing, falling off geometrically. Medians on the reference line are `lambda × (PB split on the reference line)`. We solve for the pair `(sigma, lambda)` that makes:

```
E[ min over finished attempts of the total ]  = PB
E[ sum over k of min over attempts of T_k ]   = SOB
```

This uses nested bisection over simulated 177-attempt careers (100 per evaluation, with common random numbers).

|  | sigma (log-excess) | lambda | model PB | model SOB |
|---|---|---|---|---|
| Nanobit | 0.0908 | 1.0169 | 7:01.97 | 6:51.00 |
| TexasPete (sigma pooled) | 0.0908 | 1.0172 | 6:50.00 | 6:39.04 |

**What this says.** sigma = 0.0908 is small: clean movement for these runners is very repeatable, with a split sd of about 1–2 s. Most of the gap between a typical run and a PB comes from **skip misses**, not from movement noise. The medians sit only about 1.7% slower than the PB splits, and misses add the rest.
