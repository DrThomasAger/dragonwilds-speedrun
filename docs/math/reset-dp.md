# When to reset: the dynamic program

_Generated by `scripts/analysis/docs.mjs` from `data/kb/analysis/*.json` (2026-11-03). Runpath: `D:\labyrinth\Github\JaGeX\dragonwilds-speedrun\data\kb\runpath.json`._

## Plain English

A bad first split doesn't make a sub-6:50 impossible, just unlikely. Playing it out costs minutes you could spend on a fresh attempt. The best policy maximises **sub-6:50 runs per hour of play**, not the chance per attempt. At each split, the policy says: *reset if the clock is above X*.

## Math

Let `G = 410`, `R = 45` s of reset overhead (load back in), and `r` = successes per second. Maximising the long-run rate `E[successes]/E[time]` is a renewal-reward problem. By Dinkelbach's method, the optimal rate `r*` is the unique `r` at which the best attempt has zero "profit" `E[success − r·time]`.

For a fixed `r`, define `C_k(t)` = expected profit of *continuing* into split `k` with `t` seconds on the clock:

```
W_5(t) = 1{t < G}                      (finished: 1 if under the goal)
C_k(t) = E[ −r·min(D_k, G − t) + 1{alive, t + D_k < G}·W_{k+1}(t + D_k) ]
W_k(t) = max(0, C_k(t))                (0 = reset now)
attempt profit A(r) = C_1(0) − r·R ;  r* solves A(r*) = 0 (bisection)
```

`D_k` is the split's full distribution (clean time, line delta, misses, deaths), held as a probability mass function on a 0.25 s grid built from 40,000 draws. Once the clock passes `G` the run is reset on the spot, so you pay at most `G − t`. Because `C_k(t)` falls as `t` rises, the policy is a **threshold**: continue into split `k` only if the clock is ≤ `X_k`, the largest `t` with `C_k(t) > 0`.

A forward simulation (100,000 attempts, following the thresholds) checks the DP rate. "No reset" plays every run out unless it dies.
